# BirdIndex2 Index 视频统计需求文档

| 项目 | 内容 |
| --- | --- |
| 文档版本 | V1.0 |
| 日期 | 2026-08-03 |
| 状态 | 待评审 |
| 需求类型 | 存量能力增强 |

## 1. 背景

当前 BirdIndex2 仅扫描 `JPG/JPEG/PNG/HEIC` 图片，并依据文件名将图片匹配到 IOC 分类树。分类树中的数量、扫描摘要、物种详情和导出的物种清单均只统计图片。

用户的鸟类素材目录中同时存在图片和视频。视频即使文件名包含有效的中文名或拉丁名，也不会被扫描、匹配或计数，导致 Index 不能完整反映某一分类下的实际媒体资产。

## 2. 目标

将视频纳入现有 Index 流程，在不读取或修改原始媒体内容的前提下，实现：

1. 扫描指定格式的视频文件。
2. 使用与图片一致的文件名规则，将视频匹配到 IOC 物种。
3. 在目、科、属、种各层级统计媒体总数，不区分图片数和视频数。
4. 在物种详情中查看、打开和定位匹配的视频。
5. 在扫描摘要和 Excel 物种清单中输出图片、视频的分项统计。

## 3. 成功标准

- 仅包含匹配视频、没有匹配图片的物种，也会出现在分类树中。
- 任一分类节点的媒体总数，等于该节点下命中媒体文件的数量。
- 页面统计、详情列表和 Excel 导出对同一次扫描的结果一致。
- 原有图片扫描、匹配、查看、定位和导出能力不退化。
- 全程只读，不移动、复制、重命名、删除或修改用户媒体文件。

## 4. 用户故事

作为鸟类影像资料的管理者，我希望 Index 在统计每个物种的图片时也统计视频，以便知道各分类下完整的媒体数量，并能快速打开或定位对应的视频文件。

## 5. 范围

### 5.1 本期范围

- 视频扩展名识别与递归扫描。
- 视频文件名匹配。
- 媒体类型识别及图片/视频分项计数。
- 分类树、扫描摘要、媒体列表和元数据区域的展示调整。
- 视频的系统默认应用打开与文件夹定位。
- Excel 扫描摘要及物种清单字段调整。
- 缓存兼容、自动化测试及用户文档更新。

### 5.2 非本期范围

- 视频内容识别、鸟种识别或逐帧分析。
- 读取视频时长、分辨率、编码、拍摄时间等元数据。
- 视频转码、压缩、编辑或修复。
- 在应用内播放视频。
- 为视频抽帧或生成缩略图。
- 根据同名图片与视频进行去重或关联。

## 6. 术语与统计口径

| 术语 | 定义 |
| --- | --- |
| 图片 | 扩展名为 `jpg`、`jpeg`、`png`、`heic` 的受支持文件。 |
| 视频 | 扩展名为 `mp4`、`mov`、`m4v`、`avi`、`mkv`、`webm`、`mts`、`m2ts` 的受支持文件；扩展名匹配不区分大小写。 |
| 媒体文件 | 受支持的图片或视频文件。 |
| 命中媒体 | 文件名按现有匹配规则成功匹配到一个 IOC 物种的媒体文件。 |
| 未命中媒体 | 已被识别为受支持媒体，但未匹配到 IOC 物种的文件。 |
| 命中物种 | 至少有 1 个命中图片或命中视频的 IOC 物种；同一物种只计 1 次。 |
| 媒体总数 | 图片数与视频数之和，不代表去重后的拍摄事件数。 |

统计原则：

- 每个文件路径最多计数一次；选择重叠的根目录不得重复计数。
- 图片和视频即使文件名主体相同，仍按两个独立文件分别计数。
- 不受支持的扩展名不进入扫描总数、命中数和未命中数。
- 无法访问或遍历失败的文件沿用现有容错逻辑，不计入结果；扫描不因单个文件失败而整体中断。
- 目、科、属的数量由其下级节点汇总，物种数量由匹配到该物种的媒体文件汇总。

## 7. 功能需求

### FR-01 视频扫描

1. 系统递归扫描用户选择的一个或多个根目录。
2. 除现有图片格式外，新增识别第 6 节定义的视频格式。
3. 格式识别依据文件扩展名，不读取视频内容，不校验编解码器。
4. 扫描不得跟随符号链接，根目录重叠时沿用现有去重规则。
5. 视频与图片共享一次扫描任务，不要求用户分别选择目录或启动扫描。

### FR-02 视频匹配

1. 视频使用不含扩展名的文件名参与匹配。
2. 匹配规则与图片完全一致：不区分大小写，优先匹配 IOC 拉丁名，其次匹配中文名。
3. 一个视频最多匹配一个物种，不引入多命中或人工确认流程。
4. 未匹配视频进入未命中统计，但不出现在分类树中。

### FR-03 分类树统计

1. 目、科、属、种节点均只统计 `media_count`（媒体总数），分类树中不区分图片数和视频数。
2. 物种展示为：`中文名 拉丁名（X）`；`X` 为该物种的媒体总数，中文名为空时只显示拉丁名。
3. 只有视频的物种及其上级目、科、属节点必须正常生成和展示。
4. 搜索仍按物种中文名或拉丁名进行，不因媒体类型改变搜索行为。
5. 目、科、属的媒体总数由下级节点逐层汇总，物种的媒体总数为匹配到该物种的全部图片和视频文件数量。

### FR-04 扫描摘要

扫描完成后，摘要至少展示：

- 扫描媒体总数；
- 图片总数；
- 视频总数；
- 命中媒体总数；
- 命中图片数；
- 命中视频数；
- 未命中媒体总数；
- 命中物种数；
- IOC 物种数。

所有总数必须满足对应的加总关系。为避免“扫描文件”被误解为磁盘中的全部文件，界面文案统一使用“媒体”。

### FR-05 物种媒体列表与详情

1. 现有“缩略图”区域调整为“媒体”，展示所选物种的全部图片与视频。
2. 图片沿用现有缩略图展示。
3. 视频以统一的视频占位图标、文件名和“视频”类型标识展示，本期不生成缩略图。
4. 用户单击媒体后，元数据区域展示该文件的：
   - 文件名；
   - 媒体类型（图片/视频）；
   - 完整路径。
5. 用户双击视频时，调用系统默认应用打开该视频；打开失败时给出可理解的错误提示。
6. “定位到文件夹”同时适用于图片和视频。
7. 物种详情展示：图片数、视频数、媒体总数，不再只显示含义不明确的“数量”。

### FR-06 Excel 导出

1. 导出仍为一个 `.xlsx` 文件，保留“扫描摘要”和“物种清单”两个工作表。
2. “扫描摘要”使用与页面一致的媒体统计口径，并将“原始照片未被修改”调整为“原始媒体未被修改”。
3. “物种清单”将原“照片数”列调整为以下三列：
   - 图片数；
   - 视频数；
   - 媒体总数。
4. 只有视频命中的物种必须出现在物种清单中。
5. 每行及汇总数据满足 `媒体总数 = 图片数 + 视频数`。
6. 导出文件名和现有导出流程保持不变，避免不必要的用户习惯变更。

### FR-07 缓存与兼容

1. 缓存记录必须能够确定媒体类型，不能将视频误计为图片。
2. 若现有缓存结构无法表达媒体类型，应升级缓存版本并安全失效旧缓存；失效后自动重建，不要求用户手动处理。
3. 同一目录在有缓存和无缓存情况下的扫描结果必须一致。
4. 对只包含图片的历史目录，图片数、命中物种数及分类结果应与改造前一致。

## 8. 数据结构建议

为降低前后端“Photo”命名造成的歧义，建议将媒体对象统一抽象为：

```text
MediaItem
- path: string
- file_name: string
- media_type: "image" | "video"

TaxonCount
- media_count: integer
```

物种节点持有 `media_items: MediaItem[]` 与 `media_count`；目、科、属节点只持有逐层聚合后的 `media_count`。`media_type` 用于区分媒体列表中的展示与交互，不用于分类树分项计数。扫描摘要仍按 FR-04 分别记录图片、视频及合计的扫描/命中/未命中数量。

兼容策略建议：本次版本直接将原 `count`、`photos`、`PhotoItem` 升级为语义明确的新字段，前后端同版本发布，不长期保留双套字段。

## 9. 异常与边界场景

| 场景 | 预期结果 |
| --- | --- |
| 文件扩展名为 `.MP4` 或 `.Mov` | 正常识别为视频。 |
| 视频文件名匹配某物种，目录中无该物种图片 | 物种显示，图片数为 0，视频数为 1。 |
| 同一路径因重叠根目录被扫描到多次 | 只计数一次。 |
| `白头鹎.jpg` 与 `白头鹎.mp4` 同时存在 | 图片数 1、视频数 1、媒体总数 2。 |
| 视频扩展名受支持但编码损坏 | 仍可按文件名统计；用系统应用打开失败时提示错误。 |
| 文件无扩展名或扩展名不受支持 | 忽略，不纳入任何统计。 |
| 视频未匹配物种 | 计入扫描视频数和未命中媒体数，不进入分类树。 |
| 单个文件无读取权限 | 跳过该文件，其他文件继续扫描。 |
| 扫描结果中无任何命中媒体 | 显示空分类树，允许导出空物种清单及正确的扫描摘要。 |

## 10. 非功能需求

- **性能**：在相同硬件与目录条件下，10 万个图片与视频文件的文件名扫描目标仍为约 1 分钟内完成；不得读取视频主体数据。
- **资源占用**：不得为了统计而解码视频或把视频载入内存。
- **安全与隐私**：所有扫描、匹配和缓存均在本地完成，不上传路径、文件名或媒体内容。
- **只读性**：扫描、打开、预览、定位和导出均不得修改原始媒体。
- **跨平台**：macOS 和 Windows 的扫描、默认应用打开及文件夹定位行为保持可用。
- **一致性**：页面、缓存恢复后的结果和 Excel 导出必须使用同一统计快照。

## 11. 验收标准

| 编号 | 前置条件与操作 | 预期结果 |
| --- | --- | --- |
| AC-01 | 目录包含 2 张可匹配图片和 3 个可匹配视频，均属于同一物种，执行扫描 | 该物种在分类树中显示媒体总数 5，不分项显示图片数和视频数。 |
| AC-02 | 目录仅包含 1 个可匹配视频 | 对应物种及上级分类节点正常出现，物种媒体总数为 1。 |
| AC-03 | 目录包含可匹配的 `.MP4`、`.mov`、`.M4V` 文件 | 三个文件均被识别为视频并按文件名匹配。 |
| AC-04 | 同时选择父目录和其子目录 | 同一媒体路径不被重复统计。 |
| AC-05 | 选择物种后双击一个视频 | 系统默认应用被调用；应用内不尝试播放或解码。 |
| AC-06 | 选中视频并点击“定位到文件夹” | 系统文件管理器打开并选中对应视频。 |
| AC-07 | 导出物种清单 | 工作簿包含图片数、视频数、媒体总数，数值与页面一致。 |
| AC-08 | 连续执行一次冷扫描和一次缓存扫描 | 两次的分类、图片数、视频数和合计完全一致。 |
| AC-09 | 扫描只含现有图片格式的历史测试集 | 分类结果及分类树中的媒体总数与改造前的图片计数一致。 |
| AC-10 | 目录包含 1 个匹配视频和 1 个未匹配视频 | 扫描视频数为 2、命中视频数为 1、未命中媒体数增加 1。 |

## 12. 测试要求

- 单元测试覆盖扩展名判断、媒体类型识别、文件名匹配、分类聚合与根目录去重。
- 集成测试覆盖冷缓存、热缓存、旧缓存失效、空结果和混合媒体目录。
- 导出测试读取生成的工作簿，校验工作表名称、列名、图片/视频计数及公式关系。
- 前端测试覆盖只有视频的物种、媒体类型标识、打开/定位按钮状态和错误提示。
- 回归测试覆盖现有图片格式、中文名匹配、拉丁名优先级、搜索与导出。

## 14. 评审确认项

以下为本需求文档采用的默认产品决策，评审时可调整：

1. 首期支持的视频格式为 `mp4/mov/m4v/avi/mkv/webm/mts/m2ts`。
2. 视频不生成缩略图，仅使用统一占位图标。
3. 双击视频由系统默认应用打开，不提供应用内播放。
4. Excel 保持两个工作表，在物种清单中新增“图片数、视频数、媒体总数”。
5. 分类树的目、科、属、种节点均只统计媒体总数，不展示或保存图片/视频分项计数。
